## Problem
Moneo only saves Scalable values from each sync, so the Scalable value chart and Home's "this month" change start on the day the owner connected Scalable. Before that the portfolio counts as nothing, so a newly connected portfolio looks like a gain (GitHub issue #167). We want to rebuild each past day's value from Scalable's own transactions and price charts.

## Verified real API facts (from a read-only check, tool names via `mcp.callTool`, see lib/scalable/live.ts, sync.ts, client.ts, server.ts)
- `list_portfolio_transactions` args: pageSize (max 100), cursor, cryptoCursor. Reply: `{page:{nextCursor,totalCount}, transactions:[...], crypto:{page:{nextCursor}, transactions:[...]}}`. Page until BOTH cursors are empty. `page.totalCount` is NOT reliable (said 21 with 121 rows); do not use it.
- **Crypto rows repeat across pages: dedupe by `id`.** Do the same for security rows.
- Rows: `{id, kind, category, status, currency, isCancellation, lastEventAt, security?, cash?, nonTradeSecurity?, eltif?}`. All observed status values are `SETTLED`. Only count settled, non-cancelled rows.
- `security`: `{isin, transactionType:"SINGLE", side:"BUY"|"SELL", quantity, amount}`. quantity is a POSITIVE decimal string on both sides; use side to sign it. amount is the signed cash effect (BUY negative, SELL positive).
- `cash`: `{relatedIsin, transactionType: DEPOSIT|WITHDRAWAL|INTEREST|TAX|DISTRIBUTION, amount}`, amount already signed; can be 0.
- Crypto rows: `{id, status, ticker, side, coinQuantity, quantity, amount, lastEventAt}`. **coinQuantity is the coins; `quantity` is NOT coins.** amount is signed cash like security rows.
- `nonTradeSecurity` and `eltif` rows did not occur on the real account; their shape for quantity changes (splits etc.) is unknown. If any occur, the history cannot be trusted unless the check below still passes; never guess a quantity from them.
- `get_portfolio_holdings`: `holdings[]` with `isin, position.filled (number), currentQuote.{midPrice,currency}`; `cryptoHoldings[]` is a catalog of 32 coins, most with filled 0: `{ticker,name,position:{filled},etpPositions:[{isin,name,position}]}`.
- `get_portfolio_cash_breakdown`: `cash.cashBalance` (number). `get_portfolio_overview`: `valuation.crypto` is today's crypto value in EUR.
- `get_security_chart` args `{isin, timeframe}`, reply `{currency, dataPoints:[{midPrice,timestampUtc}]}`. Spacing: `six_months` and `year_to_date` about daily; `one_year` about every 2 days; `max` monthly and back to at most ~10 years. Sold securities also return charts. Max gaps of days occur: use the latest price on or before a date (never interpolate). Merge max + one_year + six_months + year_to_date for each ISIN.
- On the real account replaying shares matched today's holdings exactly for all 18 securities, and replaying all cash amounts plus each crypto row once landed €0.02 from the balance (so the check needs a small tolerance).
- Crypto has NO chart by ticker. Estimate a coin's past price using the first of its `etpPositions` whose chart works: coinPrice(date) = etpPrice(date) × (coinPriceToday / etpPriceToday), where coinPriceToday comes from today's crypto value and coins. If no ETP chart is available, keep that coin at its buy amount.

## Build
1. **Pure calculation module** in lib/finance/ or lib/scalable/ (e.g. `lib/scalable/history.ts`): given transactions, charts, current holdings, cash, crypto value and timezone, return `{ok:true, days:[{date, securitiesMinor, cryptoMinor, cashMinor, totalMinor}]}` or `{ok:false, reason}`. One row per calendar day (workspace timezone, see lib/finance/calendar.ts) from the first transaction's date through the day before the first real synced value. Money stays integer minor units as bigint; compute share counts exactly from decimal strings, not floats. Reuse `holdingValue` from lib/finance/wealth.ts where it fits. A trade's own price (|amount| / quantity) is also a price point for that ISIN on that day. Prices in a currency other than EUR: return ok:false rather than converting.
2. **Accuracy check, required before anything is saved:** replayed shares must equal current holdings for every ISIN (tolerance 1e-6 shares), replayed coins must match held coins, replayed cash must be within €1.00 of the balance. Also ok:false if replayed shares or coins go negative on any day, or if a held security has no price for a date it was held. On failure save nothing and record the reason.
3. **Storage:** new ordered migration in supabase/migrations/ (never edit applied ones) plus lib/schema.ts: a table such as `scalable_value_history` (workspace_id, on_date, currency_code, securities_minor, crypto_minor, cash_minor, total_minor; primary key workspace_id+on_date) with RLS matching how wealth tables work (look at supabase/migrations/202611050001_scalable_connections.sql, 202611050002_scalable_wealth_sync.sql and 202610010033_wealth_history.sql), select for authenticated, writes only via service role/security-definer RPC.
