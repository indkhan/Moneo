**How transcription works:**
- **Server:** `POST /api/voice/session` requires the signed-in workspace and checks the request body with Zod. It then gets a short-lived OpenAI client secret (valid 60 s), so the real API key never reaches the browser.
- **Browser:** it opens a WebSocket to OpenAI's realtime transcription with that secret and streams the mic audio. Audio is never stored or sent to our server; only the transcript is.
- **Model:** `gpt-live-transcribe`, the only one that shows words while you speak and also accepts a vocabulary prompt. `gpt-4o-transcribe` only returns text after you stop, and `gpt-realtime-whisper` doesn't accept a prompt.
- **AI SDK:** I didn't use its realtime helpers. `getToken` only builds conversation sessions, and its streaming transcription needs a server-held socket, which a Vercel route can't keep open.
- **Live check:** I ran the flow from Node against the real API with a spoken test clip ("spent twelve euros forty cash at Netto, chips and eggs"). Words arrived about 0.4 s behind the speech and the final text was correct.

**Behaviour:**
- **Send** sends the text right away, marked `context: { input: "voice" }`, and shows a mic badge in the chat and in saved history.
- **Done** puts the text in the box to edit. **Cancel** or Escape throws it away.
- Recording stops at 2 minutes and acts like Done, so nothing said is lost. If the connection drops, what was heard goes into the box.
- **Vocabulary:** up to 80 names: account names, the most-used recent merchants and category names, all from the signed-in workspace. Names are only included when the matching AI data access is on in Settings.
- **Safari/iOS:** the mic starts inside the tap. If the browser keeps audio paused (likely on iPhone after the Voice note link), the user is asked to tap the mic.

**Tests:** `npm test` passed (1073 tests, 9 skipped), and `npm run lint` and `npm run build` are clean.
