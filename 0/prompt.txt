1. **High — “JSON only” does not make kit props or ECharts safe.**  
   Existing artifacts have an opaque-origin sandbox ([artifact-data.ts:97](lib/ai/artifact-data.ts:97)); native cards lose that boundary. A transaction description could prompt the designer to emit malicious chart options, which bypass HTML-element validation through `Kit.Chart`. ECharts explicitly documents raw HTML in `tooltip.formatter` and URL handling in `title.link`; banning functions is insufficient. [Official security guidance](https://echarts.apache.org/handbook/en/best-practices/security/).  
   **Fix:** strict schemas per kit component, rejecting unknown props. Prefer a small chart specification compiled into options by trusted code. Own tooltip rendering, links, images, toolbox actions, and event handlers. Never spread arbitrary props into React components; reject `dangerouslySetInnerHTML`, `srcDoc`, executable URLs, and prototype-related keys recursively.

2. **High — CSS scoping is not containment.**  
   Today’s frame cannot style Home; the proposed native card can. Scoped descendants with absolute positioning, extreme dimensions, negative margins, transforms or high stacking order can cover neighbours. SVG references/animation and URL-bearing presentation attributes create additional paths outside a simple `on*` filter.  
   **Scenario:** a generated “account verification” overlay captures clicks over the real dashboard.  
   **Fix:** trusted positioned, clipped, isolated card wrappers; bounded dimensions and stacking; curated style tokens instead of arbitrary CSS initially. Use a minimal SVG subset, excluding animation, `use`, external references and arbitrary `style`; namespace permitted IDs. Restrict data images by MIME type and byte size, preferably to raster formats. Build links from typed route IDs and owned entity IDs; do not accept arbitrary URLs merely because their pathname looks internal.

3. **High — QuickJS limits do not bound the whole request.**  
   Compilation, input serialization, output extraction, validation and chart rendering happen outside the proposed 50ms execution budget. Large inputs or output strings can exhaust host memory before the node cap is checked. Concurrent cards multiply this cost. QuickJS provides runtime memory, stack and interrupt controls, but those are distinct controls, not a total request budget. [Runtime documentation](https://github.com/justjake/quickjs-emscripten/blob/main/doc/quickjs-emscripten-core/classes/QuickJSRuntime.md).  
   **Fix:** if retaining execution, use a killable worker/process with bounded concurrency and total deadlines; cap source, input/output bytes, depth, strings, chart points and compilation resources. Disable imports and all host capabilities; use an explicit JSX-to-tree runtime, never execute generated modules in Node. Benchmark WASM cold starts before promising ~100ms.

4. **High — Reusable read tools need a narrower contract than chat tools.**  
   Existing saved queries validate inputs, enforce scopes and strip internal evidence ([artifact-data.ts:36–53](lib/ai/artifact-data.ts:36)). Extracting closures or exposing every nominally read tool risks losing these properties. “Read-only” also includes expensive scenarios and context-dependent detail/pagination results.
