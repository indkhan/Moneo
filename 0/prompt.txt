What changed, in commits:
1. **Step timings in the logs**: each start-up step now writes its duration to `backend.log` and `main.log`, so a slow start can be traced to one step.
2. **Services start together**: GoTrue, Storage and PostgREST now start at the same time once Postgres is up. Two database checks now run at the same time, the Postgres version comes from the bundle manifest (saving a process launch), and readiness polls every 50 ms instead of 250 ms.
3. **Next starts alongside the backend**: the server and the bank certificate start as soon as the ports are chosen. One consequence touches app code: so recovered workflows, the scheduler and the bank listener never run against a half-started database, `instrumentation-node.ts` waits for a `moneo:backend-ready` message from the main process before starting them. There's a new test for this. The source install behaves as before.
4. **Owner check**: the owner is looked up in `auth.users` instead of being re-posted to GoTrue on every start.
5. **Docs**: both desktop READMEs describe the new start order.

Things to know:
- **No true cold-disk number.** I couldn't reboot. The closest stand-in is the first launch after a fresh build, where the Next server took 36 s before and 23 s after to answer.
- **Measurement setup.** The machine was under heavy outside load (WSL, OneDrive), so I ran the two builds alternately. The numbers are from the unpacked dev build, measured before I rebased onto the updated base branch (PR #319, which had touched `desktop/src/backend/index.ts`). I kept #319's new `JWT_SECRET` env entry when resolving the conflict.
- **Tried and dropped, no gain:** Node compile cache, turning off Next's page preloading (it made first visits to other pages 0.2–0.4 s slower), showing the window at `ready-to-show`, and changing Postgres settings or connection pools. fsync is untouched.
- **Decision for you:** Storage is now the slowest backend step. Letting Home load before Storage is ready on normal starts would save about 0.7 s more, but a Storage start failure would then be reported after Home is already showing. I left it out for that reason.
