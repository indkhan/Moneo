## Findings

### 1. Required acceptance includes an optional paid-provider test — confirmed

**Evidence:** `scripts/acceptance.mjs:57` selects every browser spec except `core-journey.gated.spec.ts`. However, `e2e/scalable-trading.gated.spec.ts:13` skips without a saved session, backend configuration and `SCALABLE_MCP_ORIGIN`. The runner rejects skipped browser results and clears `OPENAI_API_KEY`. The result is a prerequisite conflict: ordinary required acceptance includes a deliberately optional provider evaluation.

**Why agents care:** An agent following the documented completion path can get blocked by an unrelated optional service, or investigate a provider failure while validating local code.

**Fix:** Explicitly separate deterministic required browser specs from opt-in provider evaluations. Keep strict skip rejection within the deterministic suite.

### 2. Merge enforcement is not established — confirmed locally; remote protection unknown

**Evidence:** No `.github` directory exists in this checkout. `package.json:13–14` exposes local acceptance commands. `scripts/acceptance.mjs:10–15` records revision and environment evidence; `scripts/acceptance.test.ts:8–22` tests stale-build rejection.

These are useful local controls, but no checked-in PR runner consumes them.

**Why agents care:** “Checks were run” remains procedural rather than an enforced property of the submitted revision.

**Fix:** Add one required hermetic PR check running privacy, unit tests, lint and build. Require it through repository rules and protect the current PR head. Run database acceptance against a disposable backend separately.
