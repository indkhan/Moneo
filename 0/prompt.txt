**`data_query`**
- **How it's locked down:** the query runs inside a function owned by `moneo_reader`, a role that can only read the views in a new `moneo_query` schema. Running inside that function means the query can't switch to `service_role`. Without it, it could, because the database connection is allowed to use that role.
- **Workspace isolation:** each view filters on a temporary table that `data_query` fills before the query runs and the query can't write. So even changing the sign-in claims inside the query doesn't reach another workspace. A view whose AI data scope is turned off returns an error.
- **Caps:**
  - The query runs read-only, and everything it changes is rolled back afterwards.
  - One statement only.
  - At most 500 rows and 200 KB, with a note when cut.
  - A 5 s timeout, confirmed through PostgREST.
- **Results:** every number comes back as exact text. Rows get formatted amounts and account/category/merchant names like other tools, and the query and result show in "tools used".
- **For the chart agent:** `runDataQuery(supabase, sql, scopes)` in `lib/ai/data-query.ts` runs a validated query and returns the rows.
