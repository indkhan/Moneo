1. **P1 — Plain artifact links can still trigger paid requests** — `app/ai/artifacts/[id]/page.tsx:44`
   
   `start` comes from the persistent `first_prompt` whenever history is empty and no request is running. If creation succeeds but the initial send fails before history is saved, opening the artifact’s ordinary link or reloading automatically retries the paid prompt. Two tabs opened before either request is recorded also both receive `start`.
   
   **Fix:** Atomically claim the initial request on the server, with an idempotency key. After failure, require an explicit retry button rather than deriving authorization from empty history.

2. **P2 — Card spending can ask unnecessarily despite a previously used card account** — `lib/ai/transaction-proposals.ts:52`
   
   `lastUsedAccount` searches every non-cash account, but `chooseAccount` accepts only checking/credit accounts for “card.” With two card accounts and a savings account, a savings transaction newer than the card transactions makes `lastUsedAccount` return savings. Neither card matches that ID, so the proposal asks for an account instead of selecting the last used card.
   
   **Fix:** Apply the same checking/credit eligibility filter when querying the most recently used account.

   **Fix:** Resolve null-account cash proposals to the existing cash account when loading account options; reserve the creation flag for cases where none exists.
