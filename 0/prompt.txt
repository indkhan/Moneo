## Goal
A chat answer or an artifact build keeps running on the server when the user closes the tab, locks the phone or navigates away. When they come back, the result is there. Only an explicit cancel stops a run. This is the base for voice notes (speak, send, close the app) and voice calls (hang up while work is running).

## Today
- `app/api/chat/route.ts` ties the run to the HTTP request. `streamText` gets `abortSignal: AbortSignal.any([request.signal, AbortSignal.timeout(90_000)])` (~line 204), there are several `if (request.signal.aborted) throw ...` checks (~lines 73, 118, 144, 243, 297), and the catch calls `cancel_chat_request` when the request was aborted (~line 310). Closing the app therefore cancels the run. The NDJSON stream already writes in a try/catch ("the reader went away; work continues"), and `finish_chat_request` already persists the answer to `messages`.
