## Bug: the Home bulk-categorize review closes itself when the last group is filed

Repro from a QA audit: Home shows "N transactions need a category" (`app/waiting-for-you-list.tsx`, entry key `uncategorized`, shown only while `review.uncategorized > 0`). Its dialog (`app/home-review.tsx`) lists uncategorized groups; with 36 groups / 72 rows, applying "Apply to all" saved everything in ~1.6 s and then the dialog vanished, taking the per-group results and the "Change" buttons with it.

Cause (confirmed in code): `categorizeGroups` in `app/home-review-actions.ts` calls `revalidatePath("/", "layout")` (line ~89; there is another at ~63 for a sibling action — check which actions run while the dialog is open). A server action that revalidates refreshes the current route at once, so Home re-renders with 0 uncategorized, the summary card is removed, and the open dialog unmounts with it.

## Fix the owner chose
Stop refreshing Home in the middle of the review: the actions the dialog calls while it is open must not revalidate the Home route. The dialog already calls `router.refresh()` in its `onClose` (`app/home-review.tsx` ~line 32), so Home updates when the owner closes it. Make sure:
- results and "Change" stay visible after the final batch, and "Change" still works (re-categorizes, undo still listed);
- other pages that show categories (Transactions, Plan/spending, etc.) are still fresh when the owner navigates there afterwards — check how Next 16 client router caching behaves here (read `node_modules/next/dist/docs/` for revalidatePath / router cache) and if needed revalidate those specific paths instead of the Home layout, or refresh on close;
- "Skip all" persistence (commit b7b20512) and the existing behaviour of every other action in that file still work.
