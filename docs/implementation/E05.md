# E05 — Editable live artifacts

Planning refinement dated 2026-09-19. This file is the canonical detail linked by `STORIES.md`; it authorizes no implementation by itself. Product Delivery baseline owns scope, architecture §§83–123 owns isolation/runtime contracts, and `WORKFLOW.md` owns delivery gates.

E05 reuses the E00-S02 QuickJS/Worker/renderer proof and existing E03 shared finance queries, E04 policy/tools/chat/confirmation, PostgreSQL tenancy, durable jobs and command journal. It does not create an arbitrary application platform, package ecosystem, browser DOM shim, second AI agent, or canonical financial write path.

## Fixed E05 decisions

- Artifact source is exactly `artifact.html`, `artifact.css`, `artifact.js` and `artifact.manifest.json`. TypeScript, arbitrary files, npm installs, CDN imports and dynamic imports are out of scope.
- The approved built-ins are the bundled artifact SDK, trusted chart primitives, formatting helpers and icons already shipped by Moneo. Adding a dependency is a security/product change, not an artifact request.
- Generated JavaScript executes from source only in QuickJS/WASM inside a dedicated terminable Worker. It never runs in the main app or renderer DOM realm.
- The trusted renderer owns DOM creation and accepts only the documented serializable UI protocol. HTML/CSS are parsed and sanitized before activation.
- Production-equivalent preview and published views use the same separate-origin renderer, CSP, Permissions Policy, protocol validation and runtime limits.
- Starting enforced limits inherit the measured E00 proof: 2 MiB total source, 16 MiB VM heap, 512 KiB stack, 1 MiB message/result, 100 runtime messages/second, 5 seconds per execution/start and Stop under 1 second. E05-S03 adds at most 8 outstanding SDK calls, 60 calls/minute/session, 500 returned rows/call and 1 MiB total result bytes. E05-S04 caps persisted state at 64 KiB. E05-S07 measures and may lower these limits; raising one requires recorded evidence and review.
- R1 finance permissions are read-only `balances.read`, `analytics.cashflow`, `analytics.spending_by_category` and `transactions.summary.read`. Raw descriptions/rows, goals/forecast APIs not yet delivered, arbitrary queries and canonical writes are unavailable.
- Artifact local state is not finance state. Canonical writes, if an artifact exposes one later, use E04's trusted host proposal/confirmation and normal command/audit/undo path.
- Compact and full are the only R1 presentation modes. Pinning to the future Home dashboard remains E07; E05 proves a saved compact view can be reopened directly.
- Normal data refresh is deterministic and uses current shared queries. It never requires an AI call. Scheduled AI refresh, export/share, public links and real-customer use are later scope.

## E05-S01 — Persist isolated artifact builds and immutable versions

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E03-S08, E00-S02

Outcome: An authorized workspace member can create an artifact draft, submit its bounded source for an isolated durable build, and activate only a validated immutable version while the prior active version remains intact.

Contracts: Product Delivery baseline artifact row and §§36–47; architecture §§83–91, 107–112, 121–123 and durability §§175–226; existing durable jobs, tenant/RLS, command journal and E00-S02 proof.

Scope: Add tenant-owned `artifacts`, immutable `artifact_versions` and build-attempt records with composite tenant keys/FORCE RLS; manifest/source/hash/status/error metadata; create-draft, submit-build, read-version and activate commands; one durable `artifact.build` job using an allowlisted child-process environment and disposable directory; reuse the proof HTML/CSS/JS validators and installed pinned compiler/runtime packages; add `test:artifact-build`.

Out of scope: Runtime viewing, Finance SDK calls, persistent state, UI editor, AI generation, npm/package installation, arbitrary filesystem/network access and broad template catalog.

Acceptance:
1. A valid four-file synthetic chart draft builds to a content-addressed immutable package, records source/build SHA-256 hashes and can atomically become active; retry/replay returns the same version/result.
2. Syntax errors, unknown files/imports/permissions, sanitizer failures, source above 2 MiB, timeout/crash and forged build output record a bounded failure and never replace the active version.
3. Foreign artifact/version/job IDs are indistinguishable from missing; concurrent activation uses expected active version and has one winner; a killed builder is recovered/fenced without duplicate versions or publication.

Invariants: Builder receives source plus synthetic validation data only—no DB URL, session, finance/provider credentials or unrestricted network. Version rows are immutable after ready/failed settlement. Hashes are server-computed.

Failure lifecycle: PostgreSQL is truth; job delivery is at least once. Generation/lease fencing protects publication. Cancel leaves the prior active version. Expired temporary directories are safely removed after validated path checks.

UI/accessibility: API/domain slice only; errors are typed for later UI. Not applicable otherwise.

Data changes: Add artifact/version/build tables, indexes, RLS and rollback that refuses to discard nonempty production tables. Existing rows: none.

Observability: Artifact/version/job IDs, status, duration, byte counts and error class only; never source, manifest values or finance data.

Limits: Fixed decisions above; one build/version, maximum 20 unsettled drafts per artifact and 10 concurrent build jobs/workspace.

Verification: `npm run typecheck`, `npm run test:artifact-build`, `npm run test:durable`, `npm run test:tenancy`, web/worker builds, deliberate-failure gate and migration rollback on a disposable PostgreSQL database.

Review focus: Credential/environment leakage, path traversal, mutable versions, stale activation, hash trust, duplicate publication and unsafe rollback.

Rollout/rollback: Feature remains hidden until S05; disable build dispatch without deleting accepted versions. Roll back code before schema; retain populated tables.

## E05-S02 — Run the trusted renderer and terminable VM

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S01

Outcome: A ready version opens through the separate-origin trusted renderer and executes in a dedicated bounded QuickJS Worker while hostile code cannot control the host, escape through browser/network authority or degrade other open artifacts.

Contracts: Architecture §§83–94, 100–106, 113–123; E00-S02 proof and measured supported browsers.

Scope: Promote the proof renderer/worker/protocol into versioned production assets; exact-origin nonce-bound MessageChannel handshake; iframe sandbox, CSP, Permissions Policy and main-app `frame-src`; bounded UI tree/patch/event protocol; per-session Worker lifecycle, Stop/Restart and activity errors; multi-artifact host limits; `test:artifact-runtime` in Chromium, Firefox and WebKit.

Out of scope: Finance RPC, persisted state, editor, AI, low-level DOM/SVG/canvas compatibility and Safari/macOS qualification.

Acceptance:
1. A valid chart/control renders in compact and full containers, keyboard interaction works at 320 px, reload/restart is deterministic, and renderer/runtime version mismatch fails closed.
2. E00 hostile cases plus forged source/origin/nonce/session messages, parent/top/self navigation, popups/forms/downloads, storage, fetch/XHR/WebSocket, external CSS/image/font, eval/Function/dynamic import, worker spawning and prototype pollution cannot exfiltrate or acquire authority.
3. Infinite loops, heap/stack/message/node/rate exhaustion and several simultaneous hostile artifacts terminate only their own sessions within limits; host health and another valid artifact stay responsive and Stop completes under one second.

Invariants: Generated JS has no Window/DOM/location/storage/network/credential objects. Renderer has no app cookie/token. No wildcard postMessage after handshake.

Failure lifecycle: Protocol/runtime/limit errors are terminal for that session, recorded, and offer Restart/Revert; they do not change active version.

UI/accessibility: Status is announced, focus remains in host controls after termination, Stop/Restart/Revert are keyboard reachable, compact/full layouts avoid horizontal overflow at 320 px.

Data changes: Add short-lived server-side runtime session records containing only authoritative user/workspace/artifact/version/protocol/nonce/expiry metadata; no source/state duplication.

Observability: Runtime/version/session IDs, counters, duration and redacted error class; no code, messages or finance payloads.

Limits: Fixed E05 limits; maximum 4 open runtime sessions/user and 2 concurrent executions/artifact, with visible refusal.

Verification: `test:artifact-runtime`, retained `test:artifact` proof suite, browser network-request capture, host responsiveness probe, builds and staging header smoke.

Review focus: Renderer-origin trust, CSP/worker inheritance, message confusion, navigation exfiltration, resource aggregate bypass and unsafe preview differences.

Rollout/rollback: Runtime feature flag and pinned runtime version; old supported asset stays available while referenced. Never activate a version requiring unavailable runtime assets.

## E05-S03 — Supply a scoped live Finance SDK

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S02, E03-S04

Outcome: Artifact code can request a small approved read-only finance subset through a server-authorized short-lived grant and automatically receives current evidence/coverage after data changes without an AI call.

Contracts: Product §§37–39; architecture §§92, 95–98, 114–116 and shared capability/tenant/policy contracts; E03 calculations/evidence and E04 exclusions/tools.

Scope: Immutable per-version permission manifest; server-derived runtime grant bound to user/workspace/artifact/version/policy/data revision/expiry; typed RPC for balances, cashflow, spending-by-category and transaction summaries backed by existing shared functions; exact decimal-string money, evidence IDs, coverage and revision; per-session quotas; grant/revocation activity; `test:artifact-sdk`.

Out of scope: Raw descriptions/rows, SQL, arbitrary filters, goals/forecast not yet implemented, provider calls and writes.

Acceptance:
1. Synthetic balance/cashflow/category/summary calls exactly match the corresponding trusted UI/E03 query results and evidence; after a second accepted import, reopening or refreshing returns the new revision with zero AI dispatch rows.
2. Account exclusion, policy change, membership/session revocation, version/grant expiry or archived artifact blocks the next RPC and stale result publication; already-open views show incomplete/revoked state rather than old full-coverage claims.
3. Forged workspace/artifact/version/method/scope/account/date/row-limit and foreign IDs fail closed without distinguishability; an artifact cannot broaden permissions by editing its manifest or messages.

Invariants: Server identity and grants are authoritative. Exclusions apply before aggregation/evidence. Money/versions stay strings. No credentials/raw SQL enter VM, renderer, Redis, logs or build artifacts.

Failure lifecycle: RPC is read-only/retry-safe. Unknown, stale, denied, quota and unavailable are typed. Late responses are discarded after revalidation.

UI/accessibility: Permission/coverage panel is readable in compact/full view; revoked/incomplete states and retry are announced and keyboard reachable.

Data changes: Version permission manifest plus bounded runtime-grant/access-event records with FORCE RLS and expiry cleanup.

Observability: Method class, permission, IDs, counts/bytes, coverage class, revision, duration and denial class only.

Limits: Fixed SDK limits; date span ≤366 days, ≤50 account IDs, ≤500 rows/call, results ≤1 MiB; raw descriptions always denied in R1.

Verification: `test:artifact-sdk` with real PostgreSQL, second-import/no-AI proof, cross-tenant/exclusion/revocation races, E03 exit, E04 policy/tools regressions and runtime browser smoke.

Review focus: Confused deputy, stale publication, derived-data exclusion, manifest trust, amount coercion, result/log leaks and quota races.

Rollout/rollback: Disable grant issuance/RPC while static artifacts remain viewable with unavailable data state; permission rows remain auditable.

## E05-S04 — Persist local state with atomic activation and revert

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S03

Outcome: Artifact-local settings persist safely across reloads and version changes, while activation/revert atomically selects a compatible code/state pair and failed migration preserves the last working pair.

Contracts: Product §§41–44; architecture §§99, 109–113; existing optimistic command/audit patterns.

Scope: Versioned JSON state schema/defaults, one current state document/artifact, expected-version patch command, bounded declarative migrations (`rename`, `remove`, `set-default` only), atomic ready-version activation plus state migration, compatible revert/reset, audit and runtime SDK get/patch; `test:artifact-state`.

Out of scope: Arbitrary migration JS, browser storage, canonical finance writes, collaborative merge/CRDT and per-user state.

Acceptance:
1. Slider/select/text state within schema persists on reopen and patch replay converges; two tabs using the same expected version have one winner and the loser receives current version/state.
2. Activation with a valid bounded migration commits code/version/state atomically; invalid schema, oversized state or failed migration leaves active code and state unchanged.
3. Revert selects a recorded compatible state snapshot or requires explicit host reset; it never runs old code against arbitrary newer state, and tenant/version swaps fail without mutation.

Invariants: State ≤64 KiB, JSON-only, schema validated server-side, no secrets/credentials/canonical money effects. Every mutation is journaled and audited.

Failure lifecycle: Commands are idempotent; row locks/expected versions prevent lost update; process death before commit has no partial activation.

UI/accessibility: Conflict preserves proposed values and offers Reload; reset/revert describes consequences and requires trusted host action.

Data changes: State document/version and immutable state snapshots/migration metadata with RLS; rollback retains state when populated.

Observability: Artifact/version/schema/state versions, byte count and outcome only.

Limits: 64 KiB state, 100 top-level keys, nesting depth 8, migration chain ≤10 operations.

Verification: `test:artifact-state` real-PG races/crash/replay/migration/revert plus SDK/runtime and command regression suites.

Review focus: Partial activation, lost updates, schema bombs, incompatible revert, state authority leakage and idempotency reuse.

Rollout/rollback: Disable mutation while last valid state remains readable; never down-migrate destructively during code rollback.

## E05-S05 — Add the manual editor and compact/full artifact views

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S04

Outcome: An authorized editor can inspect permissions, edit supported source, validate in the real sandbox, publish a new version, view history/revert, and reopen compact/full modes without endangering the active artifact.

Contracts: Product §§39–45 and editor screen guidance; architecture §§86–88, 93–94, 109–113.

Scope: Server-rendered artifact list/detail/editor with four bounded source tabs, Preview/Code/Data/Activity/Versions, validate/publish/revert/Stop controls, permission/coverage display, compact/full routes, optimistic base-version checks and preserved safe input; no new editor dependency; `test:artifact-ui` Playwright journey.

Out of scope: Full IDE, autocomplete/language server, arbitrary file tree/npm, dashboard placement, export/share and AI edits.

Acceptance:
1. Keyboard-only user edits chart label and interactive control, previews through the production-equivalent sandbox, publishes, switches compact/full at 320 px and reopens the same active version/state.
2. Invalid/unsupported code, build/runtime failure and stale base version show actionable inline errors while preserving source and the current working artifact; runaway preview remains stoppable.
3. Viewer/nonmember/foreign IDs cannot view source or mutate; permissions/coverage/data revision and version creator/time/hash are visible without exposing credentials or raw restricted data.

Invariants: Manual editing uses exactly S01/S02 validation/runtime, never raw execution. CSRF/same-origin, tenant and expected-version checks apply to every mutation.

Failure lifecycle: Draft autosave is out of scope; explicit submit is idempotent. Refresh reads durable job/version status. Cancel affects only pending build/preview.

UI/accessibility: Labels, landmarks, focus/error summary, status announcements, keyboard tabs/actions, visible Stop, no 320 px overflow and reduced-motion-safe status.

Data changes: Reuse artifact/version/build/state/activity tables; add the bounded optimistic title/description command over existing artifact metadata.

Observability: UI action class and IDs/outcomes only; no source text or finance values.

Limits: Source/state/runtime limits above; list 100 artifacts, version history 100, activity 200.

Verification: `test:artifact-ui` real browser/PG/worker critical journey, auth/CSRF/tenant probes, runtime hostile regression and web build.

Review focus: Preview bypass, stored XSS/source leakage, stale publish, authorization, keyboard/focus/error loss and misleading permissions.

Rollout/rollback: Hide editor/list flag; active runtime remains readable. Revert by activating an already-ready compatible version.

## E05-S06 — Generate and edit artifacts through contextual AI

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S05, E04-S07

Outcome: The existing persistent AI conversation can propose a new artifact or an edit against an explicit base version, but only the deterministic artifact pipeline can validate and activate it.

Contracts: Product §§43–47; architecture §§108–112, 124–174; E04 chat/tools/budgets/policy/confirmation.

Scope: Add bounded `artifact_builder` and `artifact_reviewer` capability configs using existing dispatch accounting; structured four-file/manifest output; create-draft and edit-proposal tools bound to artifact/base version/policy revision; at most one automatic repair pass; same S01 build and trusted S05 preview/publish; artifact context link from normal chat; synthetic deterministic double and bounded Nemotron-free qualification separated.

Out of scope: Second autonomous agent, automatic activation, hidden permission expansion, arbitrary finance writes, scheduled refresh, multiple-artifact generation in one request and model-authored runtime/state migrations.

Acceptance:
1. From chat, a synthetic request creates a draft chart; user previews and publishes it. A later request edits that same artifact into a scenario control and creates one new immutable candidate/version rather than a duplicate artifact.
2. Stale base/policy/data revision, malformed output, unsupported API/import, permission expansion, model outage/rate limit or failed reviewer/repair is visible and leaves the active version/state unchanged with exact usage settlement.
3. Hostile finance data/source instructions cannot alter grants, claim confirmation, bypass validation or leak secrets; model text claiming approval never activates or executes a canonical write.

Invariants: Models receive only bounded synthetic/authorized context and supported SDK contract, never credentials/raw SQL. Expected finance values remain authoritative tool results. User/host activates versions.

Failure lifecycle: Durable run checkpoints and attempt fencing; Stop/retry follows E04, idempotent draft/version keys prevent duplicates, maximum one repair pass.

UI/accessibility: Chat activity shows planning/build/review status, version/permission diff and actionable errors; Preview/Publish remain trusted host controls.

Data changes: AI run linkage on artifact/version/build/activity; reuse dispatch ledger and chat tables.

Observability: Capability/prompt/model/route, IDs, tokens/cost, validation classes and repair count only.

Limits: 1 artifact/request, 1 repair pass, 2 model calls plus normal tool calls, 20-minute wall clock, inherited route budgets and source limits.

Verification: `test:artifact-ai` deterministic structured-output, stale/prompt-injection/outage/Stop/replay tests; existing E04 suites; bounded live synthetic candidate run reported separately.

Review focus: Model as authority, grant expansion, stale overwrite, duplicate versions, prompt/data exfiltration, usage leakage and unsafe auto-fix.

Rollout/rollback: Disable artifact AI capability while manual editor/runtime remain available; accepted versions are retained.

## E05-S07 — Verify hostile and live artifact journeys and close E05

Status: Ready | Release: R1 | Epic: E05 | Dependencies: E05-S06

Outcome: A versioned synthetic evaluation and integrated supported-browser journey demonstrate that editable live artifacts are useful, refresh without AI, and preserve isolation, financial integrity and recovery under hostile/failure conditions.

Contracts: E05 epic exit; product R1 artifact commitment; architecture §§83–123 and §540 gates; all E05 stories.

Scope: Freeze fixtures/oracles before execution; integrated chart then scenario journey covering manual and AI edits, publish/reopen/compact/full/revert, second import, exclusion/revocation, Stop/restart and failed build/state migration; full hostile runtime matrix and multi-artifact limits in Chromium/Firefox/WebKit; record actual caps/durations/browser/runtime/provider versions; `test:e05-exit`.

Out of scope: Production penetration review (E08), Safari/macOS, real customer data, public sharing/export, E06 planning semantics and E07 dashboard pinning.

Acceptance:
1. Starting from synthetic imported/manual data, create/publish a chart, manually edit it, AI-edit the same artifact into an interactive local-state scenario, reopen both modes and revert; exact displayed authoritative data/evidence matches independent shared-query oracles.
2. A second overlapping import changes the live artifact on refresh with zero new AI usage; exclusion/revocation stops open and new reads/publication; stale/foreign grants and forged host actions fail without leaks/writes.
3. Failed build and failed state migration retain the working code/state pair. Infinite loop, memory/message/node/SDK floods and four simultaneous hostile artifacts are contained; host and a good artifact remain responsive and Stop is under one second in all supported browsers.
4. Manual/AI version histories, activity, exact dispatch ledger and build/runtime IDs converge under retry/process death; no duplicate active versions, state mutations or canonical financial effects.

Invariants: Every expected number/evidence is independently calculated; provider availability is separate from deterministic pass; no source/finance/secret payload in logs or committed artifacts.

Failure lifecycle: Any deterministic isolation, authorization, exactness or durability failure blocks E05. Live provider unavailable is reported unavailable, never converted to pass; failed threshold keeps E05 open.

UI/accessibility: Critical keyboard/focus/loading/error/Stop journey at 320 px plus compact/full modes across Chromium/Firefox/WebKit.

Data changes: No new product schema unless a defect requires a bounded corrective migration; evaluation results contain synthetic metadata only.

Observability: Aggregate pass/fail, browser/runtime/provider versions, durations, counts and resource maxima; redact code and finance values.

Limits: All fixed E05 caps are asserted. Dataset: at least 12 useful/empty/incomplete artifact cases and every architecture §120 hostile class, with exact expected outcomes frozen before run.

Verification: `npm run test:e05-exit`, every `test:artifact-*` suite, retained E00 artifact proof across three browsers, E03 exit, E04 critical suites, typecheck, web/worker builds, deliberate-failure nonzero, configured staging smoke, diff/tracked-secret scan and separate bounded live candidate run.

Review focus: Mock/proof substitution, hidden unsafe preview, incomplete browser coverage, stale grants/results, unsupported financial claims, resource aggregate bypass and evidence derived from implementation output.

Rollout/rollback: Keep artifact flags disabled until exit passes. Runtime assets/version data remain pinned and recoverable. Public/real-customer enablement waits for E08.
