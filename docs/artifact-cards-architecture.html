Moneo · personal finance · artifacts

Build it from your data, then live with it on Home.

An artifact is a page Moneo builds from your real finances, in its own chat. Any part of it can become a card on your Home: previewed in place, sized, published when you're happy, and drawn by the app itself — not an iframe. The model can design anything. The data always comes from the app; how a card presents it is checked by you in the preview, not by code.

Architecture

One chat, two outputs, one data contract

The artifact's chat is the normal Moneo chat with four extra tools. A designer model writes the Page or a card as isolated React. The app saves the queries the work needs and reruns them every time anything is shown, so the data is always current and app-made.

A card's life

From “add this to Home” to a card you can trust

Every step is a normal chat request, so it keeps going if you close the tab and shows as working when you come back.

1 · ask

Say it in the chat

“Add a small card with last month's total and top categories, with a month switch.”

2 · read

The agent reads real data

It uses the same read tools as chat, then writes queries with dates as meaning (@param:month.from), never fixed dates.

3 · design

Preset or its own React

If one of six shapes fits, it fills a preset. Otherwise a designer writes the card's own TSX, with any layout, several charts or custom SVG.

4 · check

Rendered before it's saved

It's compiled and run at S, M, L and XL with live data, and the tree is checked. Failures go back to the designer up to 3 times.

5 · preview

A draft, in place

The Home cards tab shows it in its Home slot between your own widgets, live and interactive. Pick a size, then ask for changes.

6 · publish

You decide when Home changes

Add to Home publishes that exact version. Later edits are drafts until “Update on Home”, and every version is kept to go back to.

Rendering

AI-written React that never runs in your browser

Page and card code run on the server inside QuickJS, a JavaScript engine compiled to WASM. Its only output is a tree of plain data, { type, props, children }. The app checks that tree and draws it with its own React, so it gets your fonts and theme, switches dark mode instantly, and has no iframe.

Measured (benchmark script in the repo)

The cost on Home is the data queries, which every widget already pays. Cards on one Home share reads: the same query runs once.

What a card can use

HTML and SVG (gradients, filters, clip paths), style objects, and scoped CSS with :hover, @keyframes and @media. The kit, which the app draws:

Kit.MoneyKit.ChartKit.TabsKit.ParamKit.LinkKit.Style

Tabs switch instantly in the browser. A Param (month, period or choice) re-renders the card on the server with new data in about 100 ms. Links are built by the app from a typed target.

Pages now use the same QuickJS and checked-tree boundary as cards. Migration 202611050001 keeps old HTML versions intact. Old designs are view-only inside an inert, scripts-disabled frame, with current query data shown separately by the app. Ask the artifact chat to rebuild its Page to restore live charts and controls; the original stays in version history.

Safety

Five walls between the model and your Home

The model writes the code, and text in your transactions could try to steer it, so we treat both the code and its output as untrusted.

LayerWhat it stops
QuickJS sandboxfresh runtime per renderNo network, files, env, timers or imports. A 1 s deadline and a 64 MB memory ceiling stop a runaway loop from stalling Home; they aren't design limits.
Tree checkallowlistOnly known HTML/SVG elements and attributes get through: no script, iframe, img, a, use, foreignObject, event handlers or dangerouslySetInnerHTML. No loading function (url(), image-set(), src() …) except url(#id) to the card's own namespaced ids, and no backslash at all, so CSS escapes can't spell one. Data can't leave through a style.
Kit schemasstrict Zod per componentUnknown props are refused. Charts take numbers and labels only, never chart-library options that accept HTML or functions. Links take a typed page plus ids, never a URL.
Scoped CSSpostcssEvery selector is prefixed with the card, keyframes are renamed, @import, loading functions and any declaration with a backslash escape are dropped, and < is escaped so CSS can't close its own style tag.
Containmentthe app's wrapperA fixed height with overflow: clip, contain: layout paint style and isolation. Even position: fixed stays inside the card, so it can't draw a fake overlay over Home.

Data

Data comes from the app and stays current; presentation is the model's

persistable reads

Every chat read tool, behind an adapter

Investigate, cashflow, transactions, detail, scenario, entities, balances, accounts, recurring, goals, wealth, forecast and agent findings. Each declares its input schema and AI scopes, which are checked again on every view. Output is made readable (formatted money, names for ids) with internal evidence stripped.

dates as meaning

“This month” stays this month

Queries save tokens such as @month_start, @days_ago:29 and @param:month.from, resolved in your timezone each view. A literal date is refused unless you asked for a fixed past period. The old approach shifted saved dates by elapsed days, so “this month” slowly became a sliding window.

params

Controls can't widen what a card reads

A request can only pick a declared option: one of the last N months, a listed period, or a listed choice. Anything else falls back to the default.

financial truth · not enforced

Money maths is instructed, not guaranteed

Enforced: the only data a card can read is the app's query results; it cannot fetch anything else. Instructed only: generated code may calculate the totals, averages, cadence equivalents and what-ifs the user requests from raw query data. Money calculations use integer minor units, currencies stay separate, and estimates and rounding assumptions must be labelled. Money is displayed with formatted strings or Kit.Money. The card is code, so it can still add amounts, mix currencies or hard-code a figure, and no check catches that. The safeguards are the agent and designer prompts, a preview of every version before it reaches Home, and version history to undo.

Decisions

What we could have built, and why we didn't

OptionWhy not (or why)
Keep one HTML doing two viewsthe old widgetNo. The widget was an afterthought of the page, an iframe of varying height that scrolled, loaded charts from a CDN and reloaded on theme change. And you couldn't see it on Home before pinning.
Card iframe with our CSS kitsandboxed, fixed sizeNo. It's safe, but it's an extra request, document and skeleton per card, and it still isn't native DOM.
JSON card document onlyreviewer's suggestionNot alone. It's simpler and safe, but caps how expressive a card can be. We kept its safety ideas (strict schemas, typed links, money through trusted components) and let the AI write real React.
Run AI React in the pagefastest to buildNever. The code would run with your session and could call any server action.
AI React in QuickJS on the serverchosenYes. It's as free as code, as fast and native as built-in widgets, and no AI code reaches the browser. The six presets go through the same pipeline from trusted source.
A separate artifact builderthe old routeReplaced. The artifact's chat is the chat, which gives it every read tool, durability, steering, cancel, the mic and attachments at no extra cost. Its build tracker table is gone.
Vercel Workflow for buildsNot now. Artifacts match chat exactly (after() + a request row). Surviving a deploy or crash mid-run is a later upgrade for both.

Tested live

What real runs found that unit tests didn't

CSS escapes

u\72l( spelled url(

Review found that CSS escapes slipped past the url() filter, so a card could have sent data to another site through a stylesheet. Any backslash in card CSS, styles or attributes is now refused, along with every loading function (url, image-set, src, …).

bundling

The WASM moved

The production build copied QuickJS's WASM file to a path that didn't exist at runtime. Fix: load the sandbox packages from node_modules (serverExternalPackages). The card e2e test now runs against next start.

frozen dates

Six queries for six months

The first month switch came back as six queries with literal dates, so it would have frozen at November. Fix: a month param with tokens, and literal dates refused unless intended.

empty sample

Guessing field names

On the 1st of the month the sample data was empty, so the designer guessed row.categoryName and every bar read “Uncategorized”. Fix: it now also sees another option's data (last month) as a shape reference.

money

Hand-made totals

The designer summed amounts and formatted them itself. Generated code is now allowed to calculate from live raw amounts as the user requests. The core app exposes amounts and currencies; it does not add a separate formula system. Exact arithmetic, currency separation and honest estimate labels remain instructions to the designer.

Limits

What still isn't perfect

No live browser maths on Home

Pages and cards support app-owned tabs and declared month, period and choice controls. Parameter changes ask the server to re-render. Arbitrary browser scripts, DOM controls and free-form sliders are unavailable.

Durability equals chat's

A deploy or crash mid-build loses that run. The request shows as failed, and you ask again.

A card can show a wrong number

The sandbox stops capabilities, not wrong arithmetic or labels: a card can compute or hard-code an amount and nothing rejects it. The preview, drafts and version history are how you catch and undo that. Enforcing it would mean cards bind to values instead of rendering them, which would cost the design freedom this version was built for.

Tailwind classes

Only classes the app already uses exist, so designed cards style themselves with style objects and scoped CSS.

Principles

The rules behind every decision

Data comes from code

Pages and cards save queries, not numbers. What a card shows from that data is the model's work, so you review it before it reaches Home.

Untrusted by default

AI code runs only in a sandbox, and its output is checked before it reaches React.

See it where it will live

The preview is the real card in its Home slot. Home changes only when you publish.

Reuse, don't fork

One chat and one set of read tools. Presets and designed cards share one render pipeline.
