Architecture

Two models, one source of truth

GPT-Live only listens and talks. Whenever you ask about your money, it hands the request off, and the browser sends it to /api/chat, the same agent and tools the text chat uses. The answer goes back to GPT-Live to say out loud. Audio goes straight from the browser to OpenAI over WebRTC; our server only opens the session, so the API key never reaches the browser.

One request, end to end

What happens when you ask “How much did I spend at Netto?”

A hand-off from GPT-Live carries no text, only a time offset in the audio. The controller takes the words you said up to that point as the request, so GPT-Live never paraphrases what you asked.

Talking like a person

Stop, queue, interrupt, correct

Each spoken request is its own small job. That one choice is what makes these four controls simple: a job can be run, stopped, held back or replaced without touching the others.

Queue

Ask three things in a row

balances?restaurants?goals?→balancesrestaurantsgoals

All three run in parallel, with no limit on how many. Results are said one at a time, in the order they finish, and only once you have been quiet for 1.5 s and Moneo has finished the previous one. A request still running after 8 s gets one short “still working on it”.

Stop

Tap Stop, or say “stop, next one”

balances: your Revol…Stop, go to the next one→recurring payments…

The Stop button cancels a running request on the server (checked before every model step), or drops an answer still waiting to be said. Saying stop, skip or “next one” over a result drops what was left of it and moves on to the next one. The command itself never runs as a request.

Interrupt

Cut in with something new

October: housing 1350, shopping…wait, my Revolut balance?→checking…anyway, back to October…

GPT-Live stops the moment you talk. The controller notices the result was cut off and keeps it. Once you are done and Moneo has answered you, it is asked to finish only the part it hadn't said. A lone “mm-hm” doesn't count as an interruption.

Correct

“No wait, I meant this month”

groceries last monthno wait, this month→this month: none yet

The new request gets the earlier ones in its brief. If you are clearly dropping one, the chat agent calls call_replace_task: the old request is stopped if it hasn't made a card yet, or else allowed to finish with its cards dismissed. The client drops its answer, and a finished answer waits up to 5 s to see whether a correction is coming.

Turn-taking

Listening to the audio, not the text

GPT-Live's transcript arrives ahead of its voice when it speaks, and about a second behind yours. So “has Moneo finished saying it?” is answered by measuring the call's audio every 100 ms, not by reading the transcript. A handful of timings decide everything:

300 msMoneo silent with your mic quiet: the result is finished, go on with the next one
2.5 sMoneo silent after you made a sound: wait in case you were talking over it
1.5 syour pause before a result is handed over (people pause mid-sentence)
600 mstranscript quiet: it has caught up with your last word
3 stime Moneo gets to answer an interruption before it goes back to the cut-off result
5 slongest an answer waits for a newer request to decide whether it replaces it
8 sa request running this long gets one “still working” note
20 slongest wait for Moneo to start a result before the next one is handed over

Tested with real speech

What live calls found that unit tests didn't

Each scenario was spoken into a fake microphone with text-to-speech and run against the real GPT-Live and chat model, then checked against the controller's timed trace. Each fix below came from a real run.

Found in nearly every run

Last word lost

“groceries last” · “month No wait…”. GPT-Live's offset points at the start of your last word (offset 5200 ms, “month” at 5200–5400 ms).

Fix: the word that starts at the offset now belongs to the request.

€5 and €15 cards

Correction after a card

“Actually make it fifteen” came after the first request had finished, so there was nothing running to replace.

Fix: the last answered request can be replaced too, and its card is dismissed.

~3.8 s to decide

Old answer said first

The correction's first step took about 3.8 s, by which time the old answer was already being spoken.

Fix: a bounded hold of up to 5 s, only while a newer request is starting.

request lost

“I'm on it”, but no hand-off

GPT-Live said “checking this month” and never handed it off.

Fix: unclaimed words GPT-Live said it was on start as a request once you are quiet.

couldn't skip

Stop a queued answer

A finished answer waiting in line had no Stop button and was always read out.

Fix: Stop stays until the answer is handed over; “stop, next one” works by voice too.

answer lost

Typed while connecting

The data channel wasn't open yet, so the answer was never spoken.

Fix: typing is only possible once the call is live.

Honest limits

What still isn't perfect

Correction after the answer is ready

If the old answer is ready before you even start the correction, Moneo may begin saying it first (about 1 in 4 runs). Preventing it would mean delaying every answer.

Two quick questions, one hand-off

GPT-Live sometimes hands off two back-to-back questions together. The agent answers both correctly, but the task list shows them as one.

Small talk tags along

“Hey, how are you” can end up at the start of the next request. The agent ignores greetings, so the answer is still right.

Principles

The rules behind every decision

Money facts come from code

The voice model never states a number of its own. Amounts come from deterministic tools, in integer minor units.

No per-request tax

No extra model calls and no blanket delays. Fixes apply only when a situation needs them, and are bounded.

One job per request

Parallel, stoppable, replaceable. Queueing, stopping and corrections all follow from this.

You stay in control

Nothing is saved until you tap, nothing is said over you, and every change can be undone.
