## 1. Leftovers after a hard kill
- **Records:** `run/services.json` now stores PID, executable path and, for Storage, the script path.
- **Next start, before Postgres starts:** a recorded process is ended only if it's alive, its executable is the recorded one, and that executable is inside the bundled backend (resolving junctions). For Storage, the recorded Node/Electron binary must also be running the recorded bundled script. Nothing is matched by name; a PID now used by another program is logged and left alone.
- **Postgres:** if `postmaster.pid` points to a live `postgres` from this bundle, or one whose command line names this data folder, it's stopped with `pg_ctl stop -m fast`. Otherwise the file is stale and is deleted.
- **What actually survives a hard kill on Windows:** only Postgres. libuv puts every child Node spawns into a kill-on-close job object, so GoTrue and PostgREST die with the parent; `pg_ctl`'s server is the one that breaks away. On macOS/Linux GoTrue and PostgREST can survive, and the PID check covers them there (not run on those platforms).
- **Storage** now exits by itself within a second once its parent is gone. A few lines at the top of the bundle watch `MONEO_PARENT_PID`.
